# 04 · AI 辅助内容与个人贡献

> 本考核允许使用 AI 辅助工具，但须**如实记录使用范围、个人贡献与验证结果**。

## 使用范围

| 环节 | AI 辅助内容 | 个人完成/修改 |
|---|---|---|
| 需求理解 | 帮助梳理 6 个验收点与参考实例 | 逐条映射到测试用例与数据设计 |
| 架构设计 | 讨论 LangGraph vs 手写循环的取舍 | 最终选定自实现决策循环 + LangGraph 状态机，并落地 |
| 代码骨架 | 生成状态图节点、工具封装的初稿 | 修复多个关键 bug（见下），重写冲突检测与优先级判定 |
| 合成数据 | 提供文档结构建议 | 亲手设计 D01/D02/D05 冲突关系与优先级声明 |
| 测试 | 提供测试框架思路 | 编写 10 个测试并逐一验证通过 |
| 文档 | 提供文档结构参考 | 全部内容基于实际运行结果撰写 |

## 个人贡献与关键修改

1. **修复跨节点状态丢失 bug**：初版用 `state["_candidate_docs"]` 跨节点传候选文档，但 LangGraph 状态合并会丢弃未声明的 key，导致「补充查证」失效。改为**从 observations 实时推导候选文档**，不依赖状态持久化。
2. **修复冲突检测的字段错位**：observation 中 `doc_id`/`content` 位于 `meta` 子字段，初版 `_detect_conflict` 直接访问顶层导致 KeyError，逐一统一字段访问。
3. **修复优先级误判（核心）**：初版用宽泛关键词「优先」判定优先级，导致 D01 的「未与 D02 声明优先级」被误判为「声明了优先级」，从而**擅自以 D01 定案**——恰好违背题目参考实例要求。改为「积极声明」（为准/最新/以本/高于/优先于）+「消极表述」（无/未/不/没有）的双重判定，确保无优先级冲突一定走追问。
4. **修复死循环**：初版「先继续查证、后检测冲突」的顺序导致读到冲突后仍继续读文档直至步数耗尽。改为「先检测冲突、有冲突立即定案/追问、无冲突才继续查证」。
5. **补充工具失败处理**：初版工具抛异常时静默产出空答案，补充 `ERROR` 分支，返回明确的 `tool_error` 状态。
6. **补充上下文追问**：实现 `_resolve_contextual_query`，代词/省略问题结合历史补全检索词。

## 验证方式

- 所有修改后均运行 `python -m pytest -v`（10 passed）与 `python -m src.main --question …` 人工核对输出。
- 冲突场景逐条核对 Trace：确认「有优先级定案 / 无优先级追问」两条路径的答案与动作正确区分。

## 边界声明

- 默认 `MockDecisionModel` 为**规则决策器**，只验证 ReAct 流程闭环与业务规则正确性，**不证明真实模型的语言理解与决策效果**。
- 真实模型入口 `ChatModelDecision` 已实现（`langchain-openai` 兼容），但因离线环境未配置 API Key，**未做真机实测**，特此说明。
